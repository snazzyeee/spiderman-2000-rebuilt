# Repository workflow

The user authorized pushing completed work and meaningful intermediate
milestones to https://github.com/snazzyeee/spiderman-2000-revamp.git on 2026-10-20.

Use that remote for subsequent authorized project work. Keep commits focused,
record validation and remaining limits, and push at useful checkpoints. A failed
or blocked check must be described accurately; never label it as passed.
Do not force push or overwrite unrelated remote changes.

Stage authored source, Unity .meta files, scenes/prefabs/settings, package
manifest/lock, project settings, build tools, and reviewed documentation.

Original game packages/executables, proprietary or converted assets, extracted
content, private reference indexes/logs, downloaded tools, Unity caches,
standalone builds, test artifacts, and machine-generated performance metadata
must remain untracked. Review the staged paths and diff before each push.

The source project opens without private assets; building Phase 1 requires a
local PC archive and the documented private conversion step.
Pushing source does not publish a binary release or assign an open-source
license; choose a license before describing this repository as open source.
