# Behavior ledger

The ledger is the middle step of the clean-room protocol:

```text
decomp / bounded binary read / TRG data  ->  docs/behavior_ledger/*.md  ->  fresh GDScript in src/
```

1. Entries state facts in our own words: numbers, thresholds, state names,
   ordering, timing and the evidence for each. They never contain decomp C++,
   disassembly, or raw executable bytes.
2. Runtime code in src/ is written from these entries, not from the decomp.
   Comments in src/ cite ledger entries, never decomp source.
3. The decomp (krystalgamer/spidey-decomp) has no license. It is fetched read-only
   at a pinned commit by tools/reference/setup_decomp.ps1 into the ignored
   tools/third_party tree and is never built, run or vendored. Its
   tools/functions/*.bin files are raw original-program bytes and are never copied.
4. The original executable is only read statically through fingerprint-gated,
   bounded tools (canonical build: PC port, SHA-256
   e4e221b168ccf52130c8c56a1535289afacc1906fb55d54545e33d50e43eec86). It is never run.
   Golden test data comes from approved remake runs, not from the original game.

## Evidence identifiers

| Form | Meaning |
|---|---|
| `decomp:<file>#<Class::Function>@f8a0392 (@Ok)` | Pinned decomp function and its upstream status tag. `@Ok` means byte-matched; `@NotOk` decompiled but not matched; `TODO` tags mean the body is a stub. |
| `exe:<rva or VA>` | Static read of the canonical executable. Values stay in private outputs under staging/reference/. |
| `trg:<LEVEL>:node<N>` | A node in levels/<LEVEL>/trg_graph.json (private, derived from original TRG data). |
| `remake:<test id>` | An approved remake measurement or golden run. |

## Confidence

- **verified**: multiple independent sources agree, or a matched decomp function plus a binary read.
- **recovered**: a single matched (`@Ok`) decomp function or exact binary decode.
- **partial**: decompiled but unmatched (`@NotOk`), or names/structure only.
- **unknown**: the behavior exists but its rule is not recovered; the remake spec is authored.

## Entry layout

Each mechanic file lists: recovered behavior, constants (value, units, evidence,
confidence), unknowns, the remake specification, deliberate deviations, and the
planned tests that will guard it.
